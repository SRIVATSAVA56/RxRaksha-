## 1. Product and hard invariants

RxRaksha takes a new prescription (typed or photographed) plus a patient profile and current medicines. It returns reconciled medicines, findings with severity, a reasoning chain and evidence per finding, and one 0-100 prototype score. Decision support for a clinician or pharmacist. It never prescribes, diagnoses or claims validation.

- **INV1** Only the rule engine creates, grades or removes a finding. The LLM only rewords one existing finding.
- **INV2** Nothing is analysed until every row is CONFIRMED or UNRESOLVED. Any UNCONFIRMED row makes `/api/reviews/analyze` return HTTP 422.
- **INV3** An UNRESOLVED medicine or allergen, or any skipped check, forces `coverage_status="partial"` and blocks every "no findings" message.
- **INV4** The app never says "safe", "clinically approved" or "no risk". Zero findings + full coverage says exactly: `No findings detected by the available rules.`
- **INV5** LLM on and LLM off give identical finding IDs, severities, counts and score.
- **INV6** OCR text is untrusted data. Never sent to the LLM, never interpreted as an instruction. OCR confidence is shown separately from name-match score.
- **INV7** Every finding carries evidence: source name, source reference, KB version, and the source's own text when present.
- **INV8** The whole demo path works offline with the LLM off.
- **INV9** A blank allergy, diagnosis, kidney or liver field is "UNKNOWN", never "none".
- **INV10** Any clinical input change after analysis marks results stale.

## 7. Domain logic

### 7.1 Normalisation (`normalize.py`)

1. Clean: lowercase, strip prefixes `tab`, `tab.`, `cap`, `cap.`, `syp`, `inj`, collapse spaces.
2. Dose regex: `(\d+(?:\.\d+)?)\s*(mg|mcg|g|ml|iu)`. A bare number right after a brand (`augmentin 625`) is brand strength: try full text against the brand index first, then text without the trailing number. No dose unit found -> `dose = null`.
3. Frequency — **try patterns longest-first** so `1-1-1-1` never matches `1-1-1`: `qid|1-1-1-1` -> "four times daily"; `tds|tid|1-1-1` -> "three times daily"; `bd|bid|twice daily|1-0-1` -> "twice daily"; `od|once daily|1-0-0|0-0-1` -> "once daily"; `hs` -> "at bedtime"; `sos|prn` -> "as needed". No match -> `null`.
4. One in-memory index at startup: `(name_norm, kind, id)` from `drug.name_norm`, `drug_alias.alias_norm` (kind GENERIC) and `brand.name_norm` (kind BRAND). `rapidfuzz.process.extract(query, names, scorer=fuzz.WRatio, limit=3)`; `match_score = score/100`.
5. BRAND candidates expand via `brand_ingredient` (`drug_ids` is a list; Augmentin -> two ids).
6. Pre-select candidate 0 only when `match_score >= 0.90`; otherwise `selected_candidate_index = null`. Status stays `UNCONFIRMED` either way. Below 0.60: candidates list is empty; the user must Edit, Remove, or mark the row UNRESOLVED.
7. `ocr_confidence` and `match_score` are separate fields, never merged.

### 7.2 Rules

| Rule | Applies to | Trigger |
|---|---|---|
| `DDI-001` | pairs of ingredient drug IDs where at least one drug is from a NEW row; skip pairs inside the same product row; skip pairs with identical drug_id | row exists in `interaction` |
| `DUP-001` | any two different rows sharing a `drug_id` | same drug in two rows |
| `ALG-EXACT-001` | NEW rows | allergen resolves to the same `drug_id` |
| `ALG-CLASS-001` | NEW rows | allergen resolves to a `drug_class` containing the drug |
| `ALG-CROSS-001` | NEW rows | allergen class is `trigger_class`, drug in `affected_class` |
| `DIS-001` | NEW rows | `disease_rule` matches drug or class and patient kidney/liver level >= `min_level` |

Allergen resolution order: `drug_class` name/alias -> drug name/alias -> brand ingredients -> unresolved allergen (to `unresolved_items`, coverage partial).

Severities: `DDI-001` = interaction row severity. `DUP-001` = MODERATE. `ALG-EXACT-001` and `ALG-CLASS-001` = CRITICAL. `ALG-CROSS-001` and `DIS-001` = table severity.

`finding_id` is deterministic: `"F-" + sha1(rule_id + "|" + sorted drug ids + "|" + factor)[:8]`. Never depends on LLM, time or row order.

### 7.3 Score

```python
POINTS = {"CRITICAL": 40, "HIGH": 20, "MODERATE": 8, "LOW": 2, "UNKNOWN": 0}

def compute_score(findings):
    raw = sum(POINTS[f.severity] for f in findings)
    score = min(100, raw)
    if any(f.severity == "CRITICAL" for f in findings):
        score = max(score, 70)
    return score
```

Engine raises -> `coverage_status="failed"`, `score=null`, no findings, engine-failure message (11.4). UNKNOWN findings: 0 points, counted as "unclassified".

### 7.4 Coverage

- `checks_run`: rule families that executed.
- `checks_not_configured` (constant): `["Dosage rules","Diagnosis-based rules","Same-class overlap"]`.
- `skipped_checks`: UNKNOWN allergy -> `{"check":"Allergy checks","reason":"Allergy status not supplied"}`; UNKNOWN kidney -> `{"check":"Kidney-related checks","reason":"Kidney status not supplied"}`; UNKNOWN liver -> same pattern.
- `unresolved_items`: UNRESOLVED medicine rows + unresolved allergens.
- `coverage_status`: `failed` > `partial` (skipped or unresolved non-empty) > `complete`. `complete` = all configured prototype checks ran, not comprehensive medical coverage.

### 7.5 Reasoning chain

Ordered `{step, text}` where step is `INPUT|NORMALIZATION|RULE|EVIDENCE|ACTION`. Built by the engine from structured fields, never by the LLM. Missing mechanism text -> `"Mechanism text not available in loaded knowledge base"`.

All JSON. Errors: `{"error":{"code":"...","message":"..."}}`, generic message, no input echoed.

### 8.1 Row shape

`source`: `EXISTING|NEW`. `origin`: `OCR|TYPED`. `ocr_confidence`: 0-1 or `null` (always `null` for TYPED). `status`: `UNCONFIRMED|CONFIRMED|UNRESOLVED`. `selected_candidate_index`: integer or `null` (see 7.1 step 6).

A row becomes CONFIRMED only when: a candidate is selected, `dose` is filled or is the literal string `"Not specified"`, and `frequency` is filled or `"Not specified"`. Enforce in UI.

### 8.3 Analyze request

```json
{
  "patient": {"label":"Synthetic patient A","age_years":67,"weight_kg":72,"gender":"MALE",
    "kidney_status":"NORMAL","liver_status":"NORMAL",
    "allergy_status":"NONE_REPORTED","allergies":[],
    "diagnosis_status":"LISTED","diagnoses":["Atrial fibrillation"]},
  "medicines": [ "every row in the 8.1 shape, status CONFIRMED or UNRESOLVED" ],
  "llm_enabled": true
}
```

`kidney_status`/`liver_status`: `NORMAL|MILD|MODERATE|SEVERE|UNKNOWN`. `allergy_status`/`diagnosis_status`: `NONE_REPORTED|UNKNOWN|LISTED`. If `LISTED` the list must be non-empty; if `NONE_REPORTED`/`UNKNOWN` it must be empty (422 otherwise). Diagnoses are stored and displayed; no rule uses them. The engine reads drug IDs from each CONFIRMED row's selected candidate. Any UNCONFIRMED row -> 422 `UNCONFIRMED_ROWS`.

  "input_revision": "sha256:...",
  "coverage_status": "complete",
  "checks_run": ["Drug-drug","Duplicate therapy","Allergy","Kidney/liver"],
  "checks_not_configured": ["Dosage rules","Diagnosis-based rules","Same-class overlap"],

                  "raw_points":60,"minimum_applied":true},
  "findings": ["..."],
  "before_after": {"existing":["..."],"new":["..."],"combined":["..."]},

`input_revision` = SHA-256 of canonical JSON of `patient` + `medicines` (sorted keys, `llm_enabled` excluded). `analysis_id` = `"A-" + input_revision[7:15]` (deterministic). `explanation_mode` = `LLM` only if at least one finding was reworded and validated; else `TEMPLATE`. Findings ordered CRITICAL, HIGH, MODERATE, LOW, UNKNOWN, then `finding_id`.

## 9. OCR (`ocr.py`)

```python
class OcrLine(BaseModel): text: str; confidence: float | None
class OcrEngine(Protocol):
    def extract(self, image_bytes: bytes) -> list[OcrLine]: ...
class OcrUnavailable(Exception): ...
```

- `TesseractOcr`: `pytesseract.image_to_data(..., output_type=Output.DICT)`, group words by line, line confidence = mean word confidence / 100 (ignore -1). Missing binary -> `OcrUnavailable`.
- `NullOcr`: always raises `OcrUnavailable` (used when `OCR_ENGINE=none`).
- Each non-empty line = one row; lines with no letters dropped; every row starts `UNCONFIRMED`; rows with `ocr_confidence` < 0.80 or `null` are highlighted.
- Phase 0 test: 5 sample images through Tesseract, record in `TODO.md`. If unusable, keep Tesseract for printed text and rely on the confirmation screen.

## 10. LLM layer (`explain.py`)

### 10.1 Templates (always produced first)

- `DDI-001`: headline `"{A} with {B}: {Severity} interaction"`; why = dataset record + mechanism, or `"Mechanism text is not available in the loaded knowledge base."`
- `DUP-001`: headline `"{Drug}: possible duplicate therapy"`; why lists the product names containing it.
- `ALG-EXACT/CLASS/CROSS`: headline `"Allergy match: {Drug}"`; why states match type with the canonical class/drug name (not the user's free text), plus mechanism for cross-sensitivity.
- `DIS-001`: headline `"{Drug}: caution with {kidney|liver} impairment"`; why = rule rationale.
- `suggested_action`: CRITICAL/HIGH `"Clinician review is required before dispensing."`; MODERATE/LOW `"Review this finding with the prescriber or pharmacist."`; UNKNOWN `"Severity is unclassified in the loaded dataset. Review manually."`

### 10.2 LLM rewording (optional)

- Only if `llm_enabled` and `LLM_PROVIDER != none`. One request per finding via `asyncio.gather`, each with `LLM_TIMEOUT_SECONDS`, temperature 0. Any error/timeout -> keep template silently.
- Send ONLY: `rule_id, risk_type, severity, affected_names, match_type, mechanism, management, possible_effects`. Never patient label, age, weight, free-text allergies, diagnoses, OCR text or dose strings.
- System prompt: `You rewrite one medication-safety finding in plain clinical language for a pharmacist. Use only the facts in the JSON. Do not add drugs, conditions, risks, numbers or advice. Do not recommend stopping, changing or replacing any medicine. Return only JSON with keys headline, why_it_matters, possible_effects, suggested_action. If possible_effects is null, write exactly: Not available in loaded knowledge base.`
- Groq OpenAI-compatible chat completions, JSON mode, key from env, behind an adapter.

### 10.3 Validator (all must pass, else template + `REJECTED_FALLBACK`)

1. Parses as JSON, exactly four keys, each a string of 400 chars or fewer.
2. Entity allowlist: one compiled regex from all KB drug names, aliases, brand names, class names (longest first, word boundaries, case-insensitive). Every match in output must be in the finding's allowed set.
3. Risk-term allowlist (`bleeding, hemorrhage, kidney failure, liver failure, qt prolongation, arrhythmia, seizure, anaphylaxis, serotonin syndrome, rhabdomyolysis, hypoglycemia, hyperkalemia, lactic acidosis, overdose, hypotension, respiratory depression`): a term may appear only if it appears in the finding's own text.
4. Every digit sequence in output must appear in the finding's own text.
5. Forbidden phrases (case-insensitive): `safe prescription, clinically approved, no risk, risk-free, guaranteed, validated, stop taking, discontinue, increase the dose, decrease the dose, switch to, replace with`.
6. If input `possible_effects` was null, output must equal `Not available in loaded knowledge base.`
7. Validator never changes severity, score, IDs or affected medicines.

On rejection: log only `rule_id` + reason code; badge `Standard explanation mode`; never show an error.
